# KiraOrder · 文案与视觉对齐提升

日期：2026-10-24。模式：Operate。以本地合成演示为检查对象，不上传原始业务材料。

## 设计判断

使用 design-taste-frontend（taste skill）与 Impeccable 的 clarify、layout、polish 方法。保留现有深蓝、薄荷、琥珀和蓝色状态体系，以及 Marcellus / Cormorant Garamond 字体。此次为已有产品的精修；开场、业务权限、接口契约和订单流转继续沿用现有实现。

taste 抽取方向为 True-black flat，seed 748144187，未重抽。采用其平面分层、颜色表达状态的原则。已有品牌规范优先于抽取方案的纯黑配色和反白主按钮；继续使用项目深蓝和薄荷主操作。产品专属结构是“原始消息 → 商品核对 → 阻断检查 → 人工批准”，不引入与任务无关的图表或装饰。

## 初始检查与整体建议

| 问题 | 对使用的影响 | 提升方式 |
|---|---|---|
| 平板保留侧栏，同时把导航缩到约 9px | 空间占用大，文字难读 | 平板使用带文字的抽屉导航，保留正常字号 |
| 状态标签宽于固定列，消息列被挤压 | 标签碰撞、客户名称和消息难扫读 | 列标题与数据行共用网格；状态可换行 |
| 手机将客户、状态、箭头塞进同一行 | 一条订单被拆得很碎 | 上行放客户与消息，下行放状态与时间 |
| “Your open orders, in one place”等重复说明 | 重要状态被低价值文字稀释 | 用真实队列数量、优先顺序替代泛化描述 |
| “1 check needs you”等含糊提示 | 不能直接理解要做什么 | 说明检查数量、确认对象和具体操作 |
| 未选全商品时仍称 Order total | 容易误认为金额已完整 | 标为 Matched subtotal，并明确不含未选商品 |
| 光晕、渐变、装饰短线同时出现 | 竞争阅读焦点 | 工作台改为平面背景和清楚的状态颜色 |
| 核对页重复小标题、口号式标签 | 信息层级过多 | 删除重复前缀，保留清楚的功能标题 |

## 视觉对齐原则

1. **共同外边线**：标题、统计区、订单区沿同一内容边界；卡片内部使用 24px 基准内边距，手机列表使用 18px。
2. **共同列线**：表头与每一行共用列定义；接收时间右对齐并使用等宽数字；状态标签不侵入时间列。
3. **光学居中**：图标明确宽高、禁止压缩；步骤圆点使用网格居中和单行行高，图标块级显示，避免文字基线带来的偏移。
4. **语义接近**：状态与阻断数量成组；客户名称与原消息成组；动作靠近其对应订单。
5. **优先级先于装饰**：首先看到需要 review 的订单和检查；标题保持品牌字体，但减少其对业务内容的压制。
6. **响应式重排**：平板腾出侧栏空间，手机将一行订单重排为身份与状态两层；保留可见时间、完整详情入口与键盘焦点。

## 文案规则

- 状态统一为 Needs review、Ready to approve、Awaiting owner、Delivery order ready。
- 指令使用“对象 + 操作”，例如询问客户包装规格后选择商品。
- 隐私掩码和人工发送方式在 Privacy & data 中说明，不在业务表单中常驻重复；审批后果、未保存与冲突恢复信息在需要时出现。
- Saved 只说明保存状态；有未解决检查时不再显示 Saved and checked。
- 不新增 SLA、紧急程度、AI 能力或真实后端已联调等事实声明。

## 后续提升建议

- 后续按同一标准收敛历史样式，优先处理审批详情和仓库的长商品名、长条件说明。
- 面向不同操作角色做一次真实任务可用性走查，检查用户能否快速找到“下一单”和审批阻断原因。
- 开场继续保持独立的沉浸体验；工作台以短反馈和清晰状态为主。设备性能应在真实手机上单独验证。

## 实施与验证结果

以上文案、列表、字号、图标与平面分层优化已落实。订单列表样式集中到 `src/styles/order-queue.css`，删除历史文件中 110 处重复选择器，避免多个断点反复覆盖同一组件。完整交付仍使用原有 API 与权限逻辑。

|---|---|
| 既有自动测试 | 57 项通过 |
| 类型契约校验与生产构建 | 通过 |
| 明暗主题 × 6 个主要页面 × 1440 / 768 / 390px | 148 项浏览器断言通过，包含页面溢出、首屏可见文字字号、状态列与图标尺寸 |

保留的 taste 提示有明确原因：双字体提示来自品牌名称与其独立副标，并非正文标题混排；主标题桌面约 37px、手机 32px 保留既有衬线品牌层级；队列与右侧任务/活动是不同长度的数据流，不强行拉高短卡片。右侧两块之间原先的额外空隙已消除。

视觉复核：首屏可以先读到待核对订单数和下一单动作；列表身份、状态和时间各有稳定位置；手机使用独立行结构。保留四张统计卡与品牌字体后，画面较初版克制且更易扫读。仍可改进的是手机核对页较长：未来可研究带状态的检查摘要跳转，需同时验证焦点顺序和未保存编辑，未在本轮仓促改变工作流。

本地截图和机器检查保存在 `.taste-skill/copy-alignment-before`、`.taste-skill/copy-alignment-final` 与 `.taste-skill/copy-final`。仅使用合成客户和商品；没有上传或发布任何业务材料。截图验证基于本机 Chrome，真实手机、Safari 和辅助技术仍需单独验收。

可长期保留的示例： [深色桌面](screenshots/taste-refined-overview-dark.jpg)、[浅色桌面](screenshots/taste-refined-overview-light.jpg)、[手机订单列表](screenshots/taste-refined-inbox-mobile.jpg)。360px 额外检查发现的顶部溢出已修复：这个宽度隐藏重复面包屑文字，保留页面主标题和全部身份/状态操作。

## 根据四处截图的进一步精简

- 删除新建订单的常驻隐私处理段落，以及原消息下重复的掩码说明；Privacy & data 保留完整解释。
- 将“1 check to resolve”与重复的 Needs review 状态合并为图标、实际数量与 pending check 标记，统一用于下一单、列表和核对区。
- 删除复制问题下的“Send manually; record the customer’s answer.”。消息仍标明 Message draft，按钮仍为 Copy question；复制成功只反馈 Copied to clipboard，不自动发送消息。
- 底部仅显示 Saved / Unsaved changes；待核对时提供 Resolve checks，点击滚动并聚焦检查区。编辑后突出 Save changes，保存前不能批准；保存后只有符合原有权限与检查条件时才能批准。没有修改时隐藏无作用的保存按钮。

追加验证：57 项既有测试通过，154 项明暗主题与业务流程断言通过；1440 / 768 / 390px 的最终检查区字号、页内定位、简洁保存状态和无横向溢出复核通过。taste 检测仍为 0 FAIL；保留提示沿用上述品牌与数据流说明。本地证据位于 `.taste-skill/copy-followup`。
